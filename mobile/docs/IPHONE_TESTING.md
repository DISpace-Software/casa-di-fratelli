# Проверка SeatMap на iPhone

## Уже сейчас: Safari-превью по Wi-Fi

Откройте на iPhone **http://192.168.1.205:5188**. iPhone и этот Mac должны быть в одной Wi-Fi сети, а сервер превью на Mac должен работать. IP Mac может измениться при переподключении к сети.

Это браузерная версия интерфейса Flutter. Она позволяет проверить экраны, языки, регистрацию, профиль, ресторанное меню и выбор столика. Она **не заменяет нативную проверку** iOS: Keychain, подпись, жесты и производительность на устройстве проверяются отдельно.

Превью использует настоящий production API на Render, включая регистрацию. Отправка формы бронирования создаёт реальную резервацию. Проверять интерфейс можно без отправки бронирования. Для браузерной проверки используйте отдельный тестовый аккаунт. Сессия Safari хранится в памяти и после перезагрузки страницы нужно войти снова.

Если сервер остановлен, на Mac:

```sh
cd /Users/macbookpro/casa-di-fratelli/mobile
/Users/macbookpro/develop/flutter/bin/flutter build web --release \
  --no-tree-shake-icons --no-wasm-dry-run \
  --dart-define=SEATMAP_API_BASE_URL=same-origin
python3 tool/serve_live_preview.py --host 0.0.0.0
```

Режим `same-origin` работает и для `127.0.0.1` на Mac, и для LAN-адреса на iPhone. Получить текущий Wi-Fi адрес Mac: `ipconfig getifaddr en0`. Если используется другой сетевой интерфейс, адрес можно посмотреть в системных настройках сети. Сервер доступен в локальной сети, публичный интернет-туннель не создаётся. Локальное превью использует HTTP; для постоянного доступа используйте HTTPS-размещение или нативную сборку.

## Настоящее приложение iOS через USB

На этом компьютере проверено: macOS 15.8.1, Intel x86_64, Flutter 3.50.0. Xcode 26.3 находится в `/Users/macbookpro/Downloads/Xcode.app`; в `/Applications/Xcode.app` осталась старая версия 15.0.1. Используйте новый Xcode. Подключённый iPhone обнаружен, Developer Mode включён, профиль подписи SeatMap создан. Проект использует Swift Package Manager, CocoaPods для текущих плагинов не требуется.

19 ноября 2026 release-сборка установлена и запущена на iPhone 14 Plus (iOS 27.0.1) с production API. Пользователь подтвердил доверие профилю разработчика; запуск подтверждён через `devicectl` и наличие процесса приложения на устройстве. Текущий профиль Personal Team истекает 26 ноября 2026: после истечения понадобится повторная подпись и установка. Это личная установка, не публикация через TestFlight.

1. На другом Mac установите **полный Xcode**, совместимый с вашей macOS и версией iOS на телефоне. Откройте его, завершите установку компонентов, ознакомьтесь с лицензией и примите её самостоятельно. Установите iOS platform support.
2. Переключите инструменты на полный Xcode и проверьте окружение:

   ```sh
   sudo xcode-select --switch /Users/macbookpro/Downloads/Xcode.app/Contents/Developer
   sudo xcodebuild -runFirstLaunch
   /Users/macbookpro/develop/flutter/bin/flutter doctor -v
   ```

   На другом компьютере подставьте фактический путь к актуальному Xcode. Важно переключить `xcode-select`: одного `DEVELOPER_DIR` недостаточно для некоторых Dart native asset hooks, которые запускаются с очищенным окружением.

3. Подключите разблокированный iPhone кабелем USB, подтвердите доверие этому Mac. Включите **Настройки → Конфиденциальность и безопасность → Режим разработчика**. iPhone может потребовать перезапуск; подтвердите включение режима после него.
4. Подготовьте зависимости и откройте проект:

   ```sh
   cd /Users/macbookpro/casa-di-fratelli/mobile
   /Users/macbookpro/develop/flutter/bin/flutter pub get
   open ios/Runner.xcworkspace
   ```

5. В Xcode добавьте свой Apple ID в Settings → Accounts. Выберите **Runner → Signing & Capabilities**, включите Automatically manage signing и укажите свою Team. Для личного тестирования подходит Personal Team. Bundle ID проекта: `com.seatmap.seatmapMobile`; при конфликте регистрации задайте свой уникальный ID. В проект уже добавлены настройки Keychain и поддержка языков bg/en/ru.
6. Получите ID телефона и запустите приложение:

   ```sh
   /Users/macbookpro/develop/flutter/bin/flutter devices
   /Users/macbookpro/develop/flutter/bin/flutter run --release -d <ID_ВАШЕГО_IPHONE> \
     --dart-define=SEATMAP_API_BASE_URL=https://casa-di-fratelli-api.onrender.com
   ```

7. Если iOS просит довериться разработчику, выполните это в настройках VPN и управления устройством на телефоне. Если Mac просит доступ к ключу подписи, подтвердите его самостоятельно.

В нативной сборке iPhone обращается к Render напрямую и не зависит от сервера превью на Mac. Сессия хранится в iOS Keychain. Для распространения через TestFlight понадобится отдельная подписанная release-сборка и настройка Apple Developer/App Store Connect; это ещё не выполнено.

Установлена на iPhone 14 Plus 24 ноября 2026; версия и сборка подтверждены через `devicectl device info apps`. После разблокировки запуск подтверждён через `devicectl device process launch`. Backend `b0715a5` опубликован, Render `dep-dc2s5h0ae00c73e7l0ag` — `live`; мобильный код — `686cd6b`. Мобильные тесты: 73 прошли, 7 условных визуальных пропущены; отдельные снимки корзины проверены с обычным и увеличенным шрифтом. Анализ без замечаний. Backend: 64 проверки предзаказов и общий набор прошли; PostgreSQL и миграция Up → Down → Up проверены отдельно.

Срок текущей личной подписи проверен в установленной сборке: 26 ноября 2026, 01:43 по Софии. После истечения потребуется повторная подпись.

- Корзина восстанавливает блюда, количество, время подачи и комментарии после закрытия приложения.
- Комментарии можно задать для каждой порции одного блюда; одинаковые комментарии объединяются в строку заказа.
- Основное действие — сохранение неоплаченного черновика. Сохранение не отправляет заказ на кухню и не проводит оплату.
- Незавершённый запрос хранится на устройстве и повторяется с тем же ключом. Сервер сохраняет историю принятых операций и защищает от дубликатов и устаревших изменений.
- При закрытом редактировании показывается объяснение и контакт ресторана; основные кнопки поддерживают крупный текст, а карта и заставка учитывают уменьшение движения.
- Ошибка записи истории на устройстве не отменяет успешную операцию сервера.

Проверка: в деморежиме добавьте две порции, задайте одной «без бекона», другой «соус отдельно», выйдите из корзины и вернитесь. Закройте приложение, откройте снова и проверьте сохранность изменений. Для реальной брони сохранённый черновик остаётся неоплаченным; не создавайте тестовые бронирования в production.

### Версия 1.0.3 (4): вкладка заказов

24 ноября 2026 установлена и запущена на iPhone 14 Plus. `devicectl` подтвердил версию 1.0.3, сборку 4 и работающий процесс приложения.

В нижней панели пять вкладок: обзор, поиск, брони, заказы, профиль. «Поръчки» / «Заказы» / «Orders» располагается перед профилем. Счётчик показывает предзаказы будущих активных броней и обновляется после сохранения. Прошедшие и отменённые визиты доступны в истории. Карточки показывают состав, отдельные пожелания, итог, статус неоплаченного черновика и доступное действие редактирования. Фотографии загружаются из меню, при их отсутствии используется иконка.

Проверить переключение всех пяти вкладок, переход из броней в заказы, активные/историю, обновление счётчика после сохранения и крупный системный шрифт. Серверных изменений для этой версии нет.

Проверки версии: 74 теста прошли, 8 условных визуальных тестов пропущены в общем прогоне. Отдельный прогон нового экрана с визуальным захватом прошёл; снимки проверены при масштабе текста 1.0 и 1.6. `flutter analyze` — без замечаний.

- При автоматическом выборе языка страна BG или регион устройства Болгария включают болгарский, даже если язык устройства английский/русский. Ручной выбор в Профиль → Език на приложението сохраняется и имеет приоритет. При неизвестной стране используются поддерживаемый язык устройства, затем английский. Страна определяется приблизительно на стороне API; GPS не запрашивается.
- Переключение между Български, English и Русский: меню, календарь, формы, ошибки, карта столов и экран результата.
- В каталоге есть **Casa di Fratelli** и **Cofein**, каждый со своим меню и планом столов.
- Регистрация, повторный вход, сохранение всех полей профиля, автозаполнение имени/телефона/email в бронировании.
- Перезапуск нативного приложения сохраняет сессию; выход завершает её на сервере. Смена пароля завершает все сессии.
- Плохое соединение и занятый стол дают ошибку; не появляется ложное подтверждение. Отправку реальной брони выполняйте только для фактического визита.
