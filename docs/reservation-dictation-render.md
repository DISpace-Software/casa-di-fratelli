# Собственное распознавание: проверка Render

17 ноября 2026. **Подготовка к отдельному платному тесту; сервис не создан.**
Production API, его тариф и голосовой ввод не изменены.

## Что уже размещено

Read-only проверка `render services --output json` подтвердила:

| Ресурс | Фактическое состояние |
| --- | --- |
| `seatmap-api` | Docker, один экземпляр, Starter, Ohio |
| Starter в актуальной линейке | `0.5c-512mb`: 0,5 CPU / 512 MB |
| Отдельный сервис речи | Отсутствует |

В опубликованной [линейке Render](https://render.com/docs/compute-plans) указаны
CPU/RAM; GPU/NVIDIA плана нет. У текущего API нет ресурсов для проверенной модели:
локальный процесс turbo занимал около 1,7 GB RSS, без учёта возможного пика и памяти
самого API. Это измерение локального процесса, не измерение Render.

## Подготовленный вариант

[`speech-service/render.yaml`](../speech-service/render.yaml) описывает **только**
новый Docker Private Service в Ohio, в том же workspace, что и API. Автодеплой
отключён. Он не берёт под управление существующие API и PostgreSQL. Ветка в файле
пока локальная: перед фактическим созданием нужно опубликовать проверенную ветку,
не сливая её с production `main`.

`render blueprints validate speech-service/render.yaml --output json` вернул
`valid: false` с единственной ошибкой: feature-ветка ещё не найдена в GitHub.
Это известный незавершённый шаг; файл нельзя считать прошедшим финальную
проверку Render до публикации ветки и повторной валидации.

Для сравнения с локальным тестом выбран `4c-8g`, четыре CPU-потока, `int8`, beam 1.
Это кандидат для измерения, а не рекомендация постоянного тарифа. Публичные цены:

| CPU / RAM | Тариф | Полный месяц |
| --- | --- | --- |
| 2 CPU / 4 GB | `2c-4g` | $85 |
| 4 CPU / 8 GB | `4c-8g` | $175 |

[Render pricing](https://render.com/pricing), проверено 17.11.2026.
[Compute оплачивается за фактическое время с посекундным расчётом](https://render.com/docs/faq).
Два часа на `4c-8g` — ориентировочно $0,49 только compute при пересчёте на 30 дней;
это не окончательный счёт с учётом build usage, налогов и других начислений.
Перед созданием нужен согласованный бюджет теста и последующее удаление именно
тестового сервиса. Оставленный работающим сервис продолжит тарифицироваться.

[`Dockerfile.render`](../speech-service/Dockerfile.render) включает веса turbo
фиксированной ревизии в образ. При старте сеть для скачивания модели не нужна;
постоянный диск не требуется. Этот Docker-образ **ещё не собран и не запущен**:
локальный Docker daemon недоступен. Проверка Blueprint не заменяет сборку образа.

## Подключение к API после успешного теста

Private Service принимает запросы только из
[того же workspace и региона](https://render.com/docs/private-network).
Адрес копируется из Render → Connect → Internal. Не следует угадывать hostname
по отображаемому имени сервиса.

Пример будущих настроек API (значения в угловых скобках требуется заменить):

```text
ReservationSpeech__Enabled=false
ReservationSpeech__ServiceUrl=http://<точный-internal-host>:8000
ReservationSpeech__TrustedPrivateHost=<тот-же-internal-host-без-схемы-и-порта>
ReservationSpeech__ServiceToken=<секрет-из-RESERVATION_SPEECH_TOKEN-worker>
ReservationSpeech__AllowedTenants__0=casa-di-fratelli
```

`TrustedPrivateHost` по умолчанию пуст. HTTP разрешается только для явно указанного
однокомпонентного DNS-имени с отдельным нестандартным портом. IP, публичные доменные
имена, credentials, query и fragment не допускаются. HTTPS остаётся стандартным
вариантом для других сред. Это доверие конкретному адресу private network, а не
TLS внутри приложения; redirects к другому адресу запрещены HTTP-клиентом.
Реальный внутренний адрес проверяется при размещении. Секрет не помещается в Git,
логи, командную строку или переменные `VITE_`.

У Private Service только [TCP health checks](https://render.com/docs/health-checks).
Uvicorn открывает порт после загрузки модели; `/health` оставлен для диагностики.
Успешный TCP check не доказывает точность распознавания или допустимую задержку.

## Что должно пройти до включения

1. Сборка pinned Docker-образа и старт без скачивания весов; отсутствие OOM.
2. Повторяемые замеры всех шести полей на самом Render, включая email, телефон,
   тишину, отмену и занятый worker. Сохранить p50/p95 и ошибки; не оценивать скорость
   только по одной удачной фразе. Предлагаемая цель UX: p95 до 3 секунд после
   остановки записи; 20 секунд — предохранительный тайм-аут, не приемлемая цель.
3. Проверка реального iPad Chrome с болгарской речью администратора, включая шум,
   разрешение микрофона, паузы и возврат после сворачивания. Автоматический WebKit
   и синтезированные WAV этой проверки не заменяют.
4. При выполнении критериев — согласовать постоянное размещение, включить API и
   соответствующую сборку админки. Если критерии не выполнены — оставить голос
   выключенным, удалить тестовый сервис и сохранить результаты.

Локальный полный сценарий turbo заполнил пять полей, но email повторно достиг
20-секундного тайм-аута. Лёгкий `small` быстрее, но ошибался в болгарских числах.
Поэтому сейчас нет основания обещать быстрое распознавание на Render или
подключать эту модель администраторам. Полный протокол:
[reservation-dictation-validation.md](reservation-dictation-validation.md).
