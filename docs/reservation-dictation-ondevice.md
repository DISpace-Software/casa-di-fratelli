## Устройство решения

Модель подготавливается автоматически при открытии формы резервации после
входа в админку и получения разрешающей политики API. Большого блока с
предупреждением о загрузке и отдельного обязательного шага подготовки больше нет:
во время загрузки показывается компактный статус, при ошибке — повторная попытка.
Администратор нажимает микрофон рядом с конкретным полем: имя или телефон.
Автоподготовка не запрашивает микрофон и не записывает звук.
Дата, час, количество гостей и email вводятся
вручную; у них нет микрофонов ни в карте, ни в списке резерваций. Приложение
записывает только эту короткую фразу, останавливает микрофон и распознаёт её
локально в Web Worker. Парсер проверяет значение выбранного поля; бронь
сохраняется только отдельным действием администратора.

Телефон сначала показывается в редактируемом черновике: поле брони изменяется
только после «Използвай този номер». Если распознана часть цифр, они остаются
видимыми для исправления; при неоднозначном тексте показываются исходные слова
и пустой черновик. Кнопка подтверждения доступна только для номера, прошедшего
проверку; при нажатии проверяется актуальная правка. Ручной ввод в основное поле
телефона, отмена или новая диктовка сбрасывают предложение.
Цифры рекомендуется произносить по одной с короткими паузами, затем нажать
«Стоп»: паузы внутри телефона больше не завершают запись. Предельная длительность
остаётся 20 секунд. Для имени сохраняется остановка после паузы или по кнопке.
UI, локальный адаптер и Worker допускают только эти два поля. Email также не
поддерживается самой моделью: в её словаре нет латинских букв.

Для этого используется болгарский Zipformer и браузерный WebAssembly runtime
sherpa-onnx. Модель и runtime размещаются вместе с сайтом — около 86 MB файлов.
Первая открытая форма может загрузить их; вход в админку без открытия формы
модель не скачивает. После подготовки
модель используется повторно между формами карты и списка до выхода из админки.
Версионированные файлы получают immutable HTTP-кэширование; большие веса также
сохраняются в CacheStorage. Запись кэша идёт небольшими порциями из уже загруженного
буфера, без клонирования ответа с дополнительной полной копией модели. Ошибка
квоты или недоступность кэша не блокирует распознавание. Кэш может исключить
повторную загрузку, но создание Worker и загрузка модели в память после
перезагрузки страницы всё равно нужны. ОС вправе очистить кэш; постоянное хранение
на физическом iPad и работа iPad в авиарежиме не подтверждены.

Для локальной записи предпочтителен AudioWorklet: он собирает PCM в памяти и
передаёт WAV без сжатия AAC. Worklet загружается с того же сайта, его граф
приглушён и не воспроизводит микрофон через динамики. Если этот путь недоступен,
до начала записи используется поддерживаемый браузером MediaRecorder; после
ошибки уже начавшаяся запись не повторяется автоматически. Ошибка декодирования
или отмена до передачи аудио в WASM сохраняет исправный подготовленный Worker.

Аудио не передаётся ни в Groq, ни в OpenAI, ни в Render API. Оно обрабатывается
в памяти. Не нужны API-ключи, подписки на распознавание, GPU или отдельный сервер.
Обычная загрузка статических файлов сайта по-прежнему использует интернет-трафик.

## Что проверяется

- Только выбранное поле; нет микрофона общего разговора.
- Запись по нажатию; телефон останавливается кнопкой или через 20 секунд,
  имя — также после паузы.
- Смена поля, ручная правка, закрытие формы и отмена исключают позднюю перезапись.
- Отмена вычисления завершает Worker, а не просто скрывает индикатор.
- Ошибка модели не включает внешний сервис автоматически.
- Неполные телефоны и неясные значения не дополняются догадками.
  Для болгарских мобильных 087/088/089 проверяется точная длина; номер с
  распознанным началом 87/88/89 без ведущего нуля остаётся черновиком, а не
  дополняется автоматически. Явные повторения цифр («три нули», «две осмици»)
  и цифровые группы с разделителями поддерживаются. Ошибочно
  распознанные слова «осемстотин» вместо цифры не преобразуются в номер.
- Локальная модель предназначена для болгарского. Переводы самого интерфейса
  сохраняются; общая админка использует только локальное распознавание.

До загрузки проверяются Web Worker, WebAssembly SIMD и декодирование аудио;
интерфейс также проверяет MediaRecorder, доступ к микрофону и защищённый контекст.
Один распознаватель использует greedy-декодирование для обоих полей. Переключение
между именем и телефоном не пересоздаёт модель и не скачивает её повторно.

## Проверка и ограничения

На Mac выполнено реальное распознавание синтетической болгарской речи в Chrome
и WebKit. Это проверка модели и браузерного runtime, а не микрофона физического
iPad или разговора в шумном ресторане.

- На этапе проверки двух полей 17 ноября прошли все 477 доменных тестов,
  включая 17 тестов локального адаптера.
- На том же этапе 25 управляемых браузерных сценариев прошли в Chrome/WebKit: карта и список,
  портретный и альбомный вид, подтверждение/отмена телефона, повторное
  использование Worker и выход из админки. Микрофонов ровно два; четыре ручных
  поля сохраняют свои значения после диктовки.
- Полный путь в форме карты Chrome: запись → декодирование → настоящий
  WASM/модель → проверка → заполнение. Имя и телефон дали ожидаемые значения;
  телефон проверен повторно и заполнялся после подтверждения.
  Подменялась только запись микрофона синтетическими WAV, распознавание настоящее.
- В итоговом прогоне двух полей подготовка на localhost заняла 5,9 с, имя —
  0,32 с, телефон — 0,56–0,58 с после остановки записи. Это измерения Mac,
  не обещание скорости iPad.
- Отдельные настоящие Chrome/WebKit-проверки подтвердили распознавание,
  повторное использование модели и CSP с `wasm-unsafe-eval`, без `unsafe-eval`.
- В полном браузерном прогоне нет запросов к voice API, внешних запросов,
  сохранения брони или ошибок страницы. В памяти WASM выделяется 512 MiB;
  полное потребление вкладки выше, и старые iPad могут не справиться.

Успешный сценарий не является оценкой точности. В более широких пробах
модель ошибалась в телефонах. На восьми синтетических номерах
паузы между цифрами улучшили greedy-результат с 2/8 до 4/8; остальные четыре
ответа отклонялись проверкой. Валидный по формату номер всё равно может содержать
неверную цифру, поэтому подтверждение обязательно. Реальная речь разных людей,
шум ресторана, микрофон и память конкретного iPad остаются непроверенными.

Отчёты сохранены локально в `output/casa-production-voice-20261117/` исходного
workspace: `ondevice-real-ui-name-phone/report.json`, `browser-bg-zipformer/`,
`native-bg-zipformer/` и `native-bg-zipformer-paused-phones/`. Они содержат
измерения синтетических проб и не входят в репозиторий.

Первый кандидат — Whisper large-v3-turbo в WebGPU — отклонён. q4f16 и fp16
encoder на проверенном AMD backend выдавали одинаковую постороннюю фразу;
q8 правильно распознал имя и телефон, но потратил примерно 43 секунды на поле.
Его код и измерения сохранены локально в `output/casa-production-voice-20261117/`
и не используются как основание обещать работоспособность на iPad.

## Общая политика API и выпуск

`GET /api/admin/context` с обычным `X-Tenant-Id` возвращает
`Cache-Control: no-store` и дополнительное поле:

```json
{
  "tenantId": "cofein",
  "reservationDictation": {
    "enabled": true,
    "mode": "on-device",
    "languages": ["bg"],
    "fields": ["guestName", "phone"]
  }
}
```

Остальные поля restaurant context сохраняются. Статическая
`ReservationDictationPolicy` читает только глобальную серверную настройку
`ReservationDictation:Enabled` (`ReservationDictation__Enabled` в окружении).
Отсутствующая настройка означает `true`; явное `false`, пустая строка или
некорректное значение отключают функцию. Нет allowlist ресторанов, проверки
Basic/Pro или отдельной настройки при подключении нового ресторана. Это
возможность платформы, а не редактируемый branding или запись в tenant-БД.
Права на создание и изменение брони остаются прежними.

Общая админка и Casa entry читают политику после входа и повторно при возвращении
фокуса или видимости вкладки. Нужны совпадающий tenant, `enabled: true`, известный
режим, болгарский язык и ровно два поддерживаемых поля. Отсутствующий, ошибочный
или недоступный контракт оставляет ручной ввод. Отключение уничтожает готовый
Worker и отменяет текущую диктовку. Изменение переменной окружения требует
перезапуска API; уже открытая вкладка применит его при следующей загрузке
политики. Build-time флаги для включения диктовки больше не используются.

Разрешение API само по себе не скачивает модель и не включает микрофон:
автоподготовка начинается при открытии формы, запись — только по микрофону.
Аудио обрабатывается только
на устройстве; `/api/admin/reservations/voice/capabilities` и `/transcribe` не
вызываются. Ошибки не переключают админку на WebSpeech или внешний сервис.
Существующий серверный ASR остаётся отдельным отключённым режимом и не нужен
этому выпуску. Не требуются новые платные ресурсы, секреты или миграции БД.

Backend commit `af01a5a` опубликован на Render. 18 ноября проверены реальные
ответы Casa и Cofein: правильный tenant, ожидаемая политика и `no-store`;
неизвестный tenant получает `404 TENANT_NOT_FOUND`. 17 новых проверок
контроллера/конфигурации и прежние tenancy-проверки проходят. Политика frontend,
адаптер и парсер прошли отдельный прогон из 190 проверок.
Отчёт production API: `output/casa-production-voice-20261117/platform-live-api-20261118.json`
исходного workspace. Фронтенд опубликован на `seatmap-admin-eight.vercel.app`;
обе production-страницы Casa/Cofein возвращают точный HTML проверенного пакета.
Перед выпуском прошли 479 доменных тестов, основная и admin-сборки, 45 браузерных
сценариев Casa/Cofein/нового tenant в Chrome/WebKit и 7 проверок отключения
политики. Проверены оба вида формы и ручные значения; подготовленный Worker
уничтожается при отключении функции. Статика и SHA256 сверены на Vercel до
переключения рабочего адреса.

На опубликованном Cofein (реальный Basic) настоящая модель обработала четыре
синтетические WAV-пробы: имя и телефон в карте, затем те же поля в списке.
Все четыре значения совпали; телефон до подтверждения оставался прежним.
Первая подготовка заняла 8,383 с, распознавание поля — 0,344–0,915 с на проверенном
Mac/Chrome. Эти числа не являются измерением скорости iPad. Модель загрузилась
один раз с того же сайта и повторно использовалась при переходе карта → список.
Разрешён один запрос входа; сохранений брони, вызовов voice API, внешнего runtime
и ошибок JavaScript не было. В существующей production-сессии Casa визуально
подтверждены оба микрофона и подготовка модели в обеих формах, без записи аудио
и сохранения данных. См. [отчёт выпуска](shared-reservation-dictation-2026-11-18.md).

## Исправления после первого выпуска — 18 ноября 2026

После сообщения о пустом поле телефона и повторном запросе подготовки проверен
настоящий путь захвата аудио. MediaRecorder/AAC в desktop WebKit превратил
тестовую фразу с «нула осем» в «осемстотин…»; прежняя проверка обоснованно
отклонила номер. Передача готового WAV в старых тестах этот дефект не покрывала.
Текущий PCM-путь проверен с настоящими AudioWorklet, декодером и моделью:
**6/6** синтетических проб совпали в Chrome/WebKit (имя и телефон, в том числе
телефон с 300 мс тишины перед речью). Это ограниченная проверка конкретных проб,
не новая оценка точности модели и не испытание микрофона физического iPad.

В текущем исправлении прошли **544 доменных теста** и итоговый прогон из
**35 управляемых UI-сценариев**. Ранее в том же цикле исправления прошёл прогон
из **51 сценария** Casa/Cofein/нового tenant; числа относятся к отдельным,
частично пересекающимся прогонам. Проверялись две формы, подготовка без записи,
повторное использование модели, отмена, ручные значения и исправление неполного
телефона. В UI-прогонах распознаватель и захват управляемые; они не заменяют
отдельную проверку настоящего PCM/ASR.

В отдельной проверке настоящей модели после перезагрузки страницы Chrome и
WebKit сделали **0 сетевых запросов за ассетами модели/runtime и передали 0 байт
этих ассетов**: модель восстановилась из кэша. Время повторной подготовки на
проверенном Mac составило 5,445 и 4,570 с соответственно. Это контролируемая
повторная загрузка, а не обещание бессрочного кэша или скорости iPad.

Локальные доказательства в исходном workspace:
`output/dictation-repeat-fix-20261118/local-browser/report.json`,
`local-browser-final/report.json`, `http-cache-report.json` в том же каталоге,
и `output/casa-voice-fix-20261118/native-pcm-final/report.json`.
Исторические сведения о первом production-выпуске выше сохранены. В опубликованном
исправлении все четыре пробы имени/телефона в карте и списке Cofein прошли через
настоящий PCM и ASR без сохранения брони. См. [отчёт исправления](reservation-dictation-fix-2026-11-18.md).

## Воспроизводимость

Модель закреплена на revision `8d2f8f4f159918a27b33c430e4fa83b10c705c28`,
sherpa-onnx — `v1.12.36`. Статика, SHA256-манифест и лицензии находятся в
`frontend/public/speech/bg-zipformer/8d2f8f4-sherpa-1.12.36/`.

Проверка 14 файлов: `python3 scripts/prepare-reservation-local-speech.py`.
Восстановление бинарников из закреплённых публичных источников:
`python3 scripts/prepare-reservation-local-speech.py --prepare`.
Загрузка из GitHub/Hugging Face нужна разработчику при восстановлении ассетов;
браузер администратора получает их только с собственного сайта.

После `npm --prefix frontend run build:admin` скрипт
`scripts/package-shared-admin.py <новый-каталог>` включает в общий пакет только
файлы модели/runtime из SHA256-манифеста и сам манифест. Проверяются источник,
revision, размер и хэш каждого файла; отсутствующие или изменённые ассеты
прерывают упаковку. Пакет содержит лицензии, MIME-заголовки для WASM/ONNX и
immutable-заголовки для закреплённого каталога модели,
поэтому не зависит от CDN модели или внешнего ASR. Одна сборка обслуживает
Casa, Cofein и новые restaurant routes; отдельные копии кода под ресторан
не нужны. Упаковка сама по себе ничего не публикует.

Браузерные сценарии: `scripts/check-reservation-local-speech-browser.mjs`
(управляемые ошибки и жизненный цикл) и
`scripts/check-reservation-ondevice-real-browser.mjs` (настоящий ASR).
Для явно разрешённой проверки Cofein production есть
`scripts/check-reservation-ondevice-production.mjs`: фиксированные адреса,
один вход, блокировка всех остальных записей, синтетический захват и настоящая
модель. Путь к файлу входа передаётся отдельным аргументом; секреты не включаются
в отчёты. Usage указан в начале скрипта.

Источники: [болгарская модель и лицензия](https://huggingface.co/preslaff/bulgarian-asr-zipformer),
[официальный sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx).
